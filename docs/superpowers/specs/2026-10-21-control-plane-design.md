# Sir Patchington design

The user authorized unattended implementation and private repository creation under their authenticated GitHub account, with safe defaults and no real model API tests. This builds the research architecture as separately reusable modules. It does not deploy into existing repositories or enable autonomous merging.

Choose a Python service with PostgreSQL durable queue rather than an Actions-only bot or twenty-two microservices. PostgreSQL coordinates API replicas and worker replicas; tenant/team/repository policies scope all work. A process boundary separates credential-bearing source/model access from untrusted execution, and a separate publisher reconstructs a frozen tested candidate before a compare-and-swap Git push. Default policies permit unattended review/repair/verification but require explicit exact-candidate approval and publish enablement. Production startup rejects development storage, fixture models and unsafe configuration.

Data flow: signed bounded webhook → authorized repository mapping → deduplicated durable queue → authoritative GitHub reconciliation → pinned source/context/requirements → risk routing → deterministic and semantic findings → independent skeptical decisions → bounded repair → frozen candidate → clean independent checks → content-addressed evidence → authenticated exact-artifact approval → restricted publisher → remote readback → CI/rereview/outcome ledger. No model controls credentials, acceptance commands, queue fences or publication authority.

Implement shared strict immutable contracts; transactional leasing/fencing/per-PR exclusion and tenant quotas; GitHub App authentication with scoped installation tokens and complete pagination; lexical/Python-AST provenance-backed context and impact routing; structured fixture/Claude-CLI model adapters; safe Git candidate construction; networkless constrained container verification; RBAC API and audit/outbox records; reconciliation and bounded attempts; metadata audit/outbox exports; deployment manifests and runbooks. Expose unsupported language graph, hardware and production deployment qualification explicitly rather than manufacture green evidence.

Verification uses real temporary Git repositories, HTTP transport fixtures, PostgreSQL and Docker locally; provider/model generation is prohibited. Test races, stale leases, duplicate/out-of-order events, tenant escapes, protected paths, symlinks, malformed output, mutated evidence, approval expiry, wrong revisions and ambiguous writes. Do not label local validation as proof of production scale or model quality.
